# ผลทดสอบและรายการตรวจรับ

ตรวจวันที่ 10 กันยายน 2569 ผลด้านล่างเป็นการทดสอบซอร์สในเครื่องพัฒนา ไม่ใช่ผลตรวจรับเครื่อง production ของมหาวิทยาลัย

## Automated tests

| คำสั่ง | ผลล่าสุด |
|---|---|
| php artisan test | ผ่าน 18 tests / 155 assertions บน SQLite ในหน่วยความจำ |
| php scripts/test-mysql.php | ผ่าน 18 tests / 155 assertions บนฐานข้อมูล MySQL/MariaDB ชั่วคราว |

ทดสอบด้วย PHP 8.2.12, Laravel 10.50.2, PHPUnit 10.5.64 และ MariaDB 10.4.32 บน Windows/XAMPP สคริปต์ MySQL สร้างฐานข้อมูลใหม่และรัน migrations จริงครบก่อนทดสอบ จากนั้นลบเฉพาะฐานข้อมูลชั่วคราวของสคริปต์เอง

## การตรวจเพิ่มเติมในเครื่องพัฒนา

- `npm run build` ผ่านด้วย Vite 5.4.21
- `composer validate --no-check-publish`, `composer check-platform-reqs`, การ compile Blade และ `git diff --check` ผ่าน
- ชุด ZIP สร้างจากรายการไฟล์ที่อนุญาต ตรวจ manifest/SHA-256, ลิงก์คู่มือ และการไม่รวมข้อมูลจริง/รหัสลับแล้ว
- อัปเกรดฐานข้อมูลเดิมหลังสำรองสำเร็จ
- ย้ายไฟล์เดิม 18 ไฟล์เข้า private storage และไม่พบ references ที่ชี้ไฟล์หาย
- ซ้อมนำ SQL backup กลับเข้าฐานข้อมูลชั่วคราว แล้วอัปเกรด migrations สำเร็จ จำนวนแถวในตารางหลัก 6 ตารางคงเดิม
- ตรวจเนื้อหาไฟล์แนบ 18 ไฟล์ใน backup เทียบไฟล์ private หลังย้ายตรงกัน
- ทดลอง DemoSeeder ซ้ำในฐานข้อมูลชั่วคราว ได้คำขอสมมติ 2 รายการโดยไม่เพิ่มซ้ำ

การซ้อมกู้คืนข้างต้นตรวจฐานข้อมูลและเนื้อหาไฟล์ในเครื่องพัฒนา ยังต้องซ้อมเปิดใช้งานบนเครื่องปลายทางด้วยบัญชีและการตั้งค่าของมหาวิทยาลัย

## สิ่งที่ครอบคลุม

- ยื่นคำขอจริงผ่าน HTTP test พร้อมไฟล์ PDF และภาพลายเซ็น และตรวจเก็บไฟล์ใน private storage
- กรอกรหัสและอีเมลเดิมไม่เขียนทับผู้ขอในคำขอเก่า
- วันที่ไม่ถูกต้อง ไม่ยอมรับข้อกำหนด หรือไม่เลือกการรับรองค่าใช้จ่าย ไม่สร้างคำขอหรือไฟล์
- เปิดหน้าแรก แบบฟอร์ม รายละเอียดคำขอ รายการบัญชี โดเมน เจ้าหน้าที่ และหน้าแก้ไขที่ใช้ใน workflow
- สร้างบัญชีก่อนอนุมัติไม่ได้; กดอนุมัติซ้ำไม่เพิ่มประวัติ; อนุมัติไม่ออกเลขใบเสร็จ
- คำขอ rejected ไม่ถูกอนุมัติหรือสร้างบัญชีผ่านการยิง route โดยตรง
- สร้างบัญชีซ้ำในคำขอเดียวกันไม่ได้แม้เปลี่ยน username; ชื่อผู้ดำเนินการที่ปลอมใน payload ไม่ถูกนำไปใช้
- เก็บ password hash; หน้าแก้ไขปล่อยรหัสผ่านว่างแล้วรหัสเดิมยังใช้ได้
- ต่ออายุ บันทึกประวัติ ป้องกันวันย้อนหลังและส่งฟอร์มเดิมซ้ำ; คง disabled หลังต่ออายุ
- แก้คำขอ legacy ที่ใช้ applicant ร่วมกันไม่เปลี่ยนคำขออีกใบ
- ไฟล์แนบเปิดได้เฉพาะเจ้าหน้าที่ active; ไฟล์หาย ชนิดไม่รู้จัก และ path ไม่ถูกต้องตอบ 404
- ย้ายไฟล์เก่าแบบ dry-run และจริง ตรวจเนื้อหา รันซ้ำได้; ไม่ลบต้นฉบับถ้าปลายทางต่างกัน
- seed master ซ้ำไม่เพิ่มรายการหรือทับราคา ไม่มีบัญชีรหัสผ่านสำเร็จรูป
- สร้างเจ้าหน้าที่ผ่านคำสั่ง ทดสอบ login/logout และป้องกันปิดบัญชีตัวเอง

## ขอบเขตของหลักฐาน

HTTP tests เรียก controller, middleware, validation, Blade และฐานข้อมูลผ่าน Laravel test client การทดสอบนี้ไม่ได้เปิด browser เพื่อตรวจภาพจริง ไม่ได้ส่ง SMTP จริง ไม่ได้เรียก Plesk และไม่ได้จำลอง load หรือ race condition พร้อมกัน การทดสอบ retry/กดซ้ำเป็นคำขอตามลำดับ
